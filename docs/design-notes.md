# 设计说明与踩坑记录

这份文档写给"想改这个项目的人"，回答三个问题：**为什么这么写**、**哪里曾经炸过**、**怎么验证的**。

## 1. 数据流

```
schtasks (每天 20:00)
  └─ wscript run-hidden.vbs        隐藏窗口 + 把 node 的退出码回传给任务计划程序
      └─ node main-outlook.mjs
          ├─ lib/window.mjs        算窗口起点（标准化到 20:00，且保证不漏）
          ├─ lib/bridge.mjs → outlook-bridge.ps1 -Dump    读收件箱 → JSON
          │       └─ 顺手写 .state/inbox-meta.json（收件箱总数 / 见到的最新邮件）
          ├─ lib/commands.mjs      分出"待办指令邮件"（白名单 + 标记词两道闸）
          ├─ lib/rank.mjs          LLM 分档：action / watch / info
          ├─ lib/pending.mjs       action 邮件进「重要提醒」清单，跨天带出
          ├─ lib/enrich.mjs        LLM 翻译 + 生成「要做什么」+ 抽待办
          ├─ lib/todos.mjs         并入台账（按线程去重、校验日期、过期归档）
          ├─ lib/threads.mjs       其余邮件按来源归并
          ├─ lib/digest.mjs        渲染 HTML（发信）+ Markdown（本地存档）
          └─ lib/bridge.mjs → outlook-bridge.ps1 -Send    发到你的私人邮箱
```

## 2. 为什么用 Outlook COM，而不是 Microsoft Graph

这是整个项目最关键的一次技术选择，过程值得记录：

1. Graph 是官方路线，但对**学校租户**基本走不通：注册的应用需要 `Mail.Read`/`Mail.Send` 的
   **管理员同意**，PolyU 关闭了用户自助同意，授权页直接显示「需要管理员批准」。
2. 换用微软第一方公共客户端（Graph CLI / Office / Azure CLI）绕开注册，仍然被拦：
   Office 客户端请求 Graph token 会被 `AADSTS65002` 拒绝。
3. **Outlook 桌面 COM** 不需要任何授权：它借用你**已经登录**的 Outlook 会话。
   代价是必须 Windows + 桌面版 Outlook，而且读的是本地缓存（OST），存在"还没同步完"的问题
   ——这一点直接决定了下面第 4 节的设计。

结论：在"学校邮箱 + 无管理员权限"这个约束下，COM 是唯一可行路线。
代码里 `lib/graph.mjs` 那条线已删除，只在文档里留档这个结论。

## 3. LLM 与代码的职责分界

**模型只负责"从自然语言里读出意思"，代码负责所有"决定"。**

| 交给模型 | 留在代码里（确定性、有测试） |
|---|---|
| 这封邮件要不要我动手（action/watch/info） | 窗口推进、去重、排序、渲染 |
| 翻译成中文、概括"要做什么" | 日期合法性校验（模型编的日期会被丢掉） |
| 从指令邮件里读出操作意图 | 操作落地（找不到对应待办就不动）、幂等 |
| 主题的中文标签 | 过期归档、保留天数、备份与原子写 |

两条硬规则：

- **模型返回的东西一律二次校验**：`due` 必须形如 `YYYY-MM-DD` 且在过去一年多 / 未来两年多之内；
  `id` 必须真实存在；对不上的操作**宁可不改**，只在日报里报告"未识别"。
- **纯回执走代码直通**：正文只有「收到/已读/搞定了」时，不调用模型，直接销「重要提醒」清单。
  既省一次 API，也不受模型波动影响。
- **「加一个」永远不等于「改期」**（见 §8，2026-09-23 真实事故）：
  回信里出现 `加一个/新增/添加/补充/再加/记一下/加进`，且一个字都没提
  `改期/推迟/延后/改成/换成/提前/挪到` 时，模型给的 `set_due` **一律降级成新增一条**，
  已有待办的日期原封不动。改期那一行必须写成 `旧日期 → 新日期` 并附上可照抄的撤销指令。

## 4. 窗口：标准化到 20:00，但绝不漏邮件

用户的规则是"日报覆盖前一天 20:00 → 当天 20:00 这 24 小时，跑晚了就一直到最新的"。
但桥接层读的是 **Outlook 本地缓存**：刚开机时缓存可能还没同步完，会**读到 0 封**。
如果无脑按墙钟推进窗口，那批其实已到达的邮件就**永久跳过**了。

所以维护一个"覆盖点"（watermark），它**只随真正读到的最新邮件前进**，读到 0 封时原地不动；
窗口起点取"标准起点"和"覆盖点"里更早的那个：

| 情形 | 读取起点 | 日报显示 |
|---|---|---|
| 正常每天 20:00 | 略早于标准起点 | `09/20 20:00 → 09/21 20:00` |
| 20:30 才跑 | 同上 | `09/20 20:00 → 09/21 20:30`（终点延伸） |
| 白天手动跑过 | 仍从昨天 20:00 | 标准 24 小时，重叠靠"已报告名单"过滤 |
| 关机两天补跑 | **从上次覆盖处补起** | 如实放宽并说明原因 |

这份逻辑是纯函数（`lib/window.mjs`），由测试守着，其中两条底线：
**"读到 0 封时覆盖点不许推进"** 和 **"关机两天不能只报最近 24 小时"**。

### 缓存没同步完：重读一次，以及一条差点变成假警报的守卫

覆盖点是"上次见到的最新邮件 **+1 秒**"，所以**收件箱安静的时候，里面最新的邮件恰好就早这 1 秒**。
一开始的守卫写的是"读到 0 封、且最新邮件早于覆盖点 → 疑似缓存没同步完，等 60 秒重读"——
于是每个没有新邮件的运行都会白等 60 秒、还发一条吓人的 ⚠️ 警告（2026-09-23 13:59 实测误报）。
（真正的缓存停滞是**分钟级**的：9/22 21:19 已覆盖，9/23 却只看到 20:53。）

现在的判据：

| 情况 | 处理 |
|---|---|
| 见到的最新邮件比覆盖点旧 **2 分钟以上** | 真的倒退了 → 等 60 秒重读（2026-09-22 那次 130+ 封事故就是这个信号） |
| 比覆盖点旧不到 2 分钟（就是我们自己那 +1 秒） | 正常安静 → 立刻继续 |
| 连"见到的最新邮件"都没有 | 更像没同步完 → 重读一次 |
| 最新邮件早于窗口起点 | **不再**重读（那只是这段时间真没邮件，重读一次也是空的） |

另外 `nextWindowStart` 现在**只前进不后退**：缓存没同步完时，见到的最新邮件可能比覆盖点还旧，
照它推进会把窗口拉回去、重复报旧邮件。

**English** — The coverage point is *last seen mail + 1s*, so a quiet inbox always looks "1 second
older than covered". The retry guard now uses a 2-minute tolerance (real cache stalls are minutes
long), no longer retries merely because the newest mail predates the window, and the coverage point
can only move forward.

## 5. 状态文件：写前备份 + 原子写

`.state\` 里是这台机器的"记忆"：待办台账、重要提醒清单、已处理指令、窗口位置、翻译缓存、
以及**自动备份**（`backups\`，保留最近 10 份）。

这一套是被真实事故逼出来的：一次清理临时文件时误用了通配符（`.state\t*.json`），
把台账连同缓存一起永久删掉了（PowerShell 的 `Remove-Item` 不进回收站），
而程序当时的反应是——读不到文件就当成"新用户"，用空台账覆盖回去，一声不响。

现在三道防线（`lib/statefile.mjs`）：

1. **写盘前自动备份**旧内容 → 误删/误覆盖都能用 `restore-ledger.cmd` 一键还原；
2. **原子写**（先写临时文件再改名）→ 断电/被强杀/两个任务撞车都不会留下半截 JSON；
3. **读不出来就大声报，并且不覆盖** → 原文另存为 `backups\*-corrupt-*.json`，跳过本次保存。

> 教训：**永远不要对 `.state\` 用带通配符的删除**，要删就逐个点名。

## 6. Windows 相关假设（都真实踩过）

| 事项 | 说明 |
|---|---|
| `.cmd` 必须**纯 ASCII** | `cmd.exe` 按 ANSI 读批处理，UTF-8 中文字节会让偏移错位、吞字符（`schtasks` 变 `ks`），脚本一闪就没。有测试守卫 |
| `.ps1` 必须**带 UTF-8 BOM** | 否则 PowerShell 5.1 按 GBK 读，中文注释乱码并撑爆语法。有测试守卫 |
| Outlook 路径 | `outlook-bridge.ps1` 里写的是 `C:\Program Files\Microsoft Office\Root\Office16\OUTLOOK.EXE`，版本/盘符不同就找不到，需要改 |
| 必须是**已登录的交互式会话** | 计划任务用的是交互式令牌（注销状态不跑）；发信时可能弹出"某程序正代表你发送邮件"，不点允许会卡住 |
| `logs\task.log` 是 **UTF-16LE** | 因为它是 `cmd` 重定向写出来的；用 `Get-Content -Encoding Unicode` 读（用 UTF8 会报 `line is not valid UTF-8`） |
| 桥接会**就地 Sort 收件箱 Items 集合** | 这是借用了 Outlook 的视图排序，属于对用户客户端的副作用 |
| 沙箱/CI 里跑不了 COM | 会报 `0x80080005`；生产不受影响（计划任务不在沙箱里） |
| 别对 `.state\` 用通配符删除 | 见上一节，事故就来自这里 |

## 8. 一次真实事故：我想「加一个」，结果旧任务的日期被改了

一封 AMA 期中考试通知（11/1）到了，用户回信说「加一个」。模型输出 `set_due`，代码照做 ——
新任务没进来，已有任务 `AMA as1` 的 `10/23` 被覆盖成 `11/1`，**旧日期就此丢失**。

两条修法：

1. **代码兜底**：回信里出现「加一个/新增/添加/补充/再加/记一下/加进」，且一个字都没提
   「改期/推迟/延后/改成/换成/提前/挪到」时，`set_due` 一律降级成**新增**，
   已有待办的日期原封不动。宁可多一条待办，也不能悄悄改掉一张已经记好的日期。
2. **可见 + 可逆**：改期那一行必须写成 `🔁 改期：AMA as1　10/23 → 11/01`（旧日期一起显示），
   并在段落末尾给出原话级别的撤销指令：`回信写「↩️ AMA as1 改回 10/23」即可撤销`。
   改错这件事，必须在你看到日报的下一秒就能发现、一句话就能改回来。

**English** — Model owns natural-language meaning; code owns the add-vs-reschedule safety net.
If a reply says *add* (and never says *reschedule*), a `set_due` op is downgraded to a new item
and no existing due date is touched. Every date change is rendered as `old → new`, followed by a
copy-pasteable undo line.
